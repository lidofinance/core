# fix(sr): cap 0x02 top-up reservation at the gateway target balance (#2043)

Closes #2043

## Summary

The Staking Router reserved top-up budget for WC `0x02` modules using the theoretical
`maxEBType2` ceiling (2048 ETH per validator). `TopUpGateway` only funds up to
`targetBalanceGwei` (2046.75 ETH on mainnet) and returns zero once the remainder is below
`minTopUpGwei`. Validators already topped up to 2046 ETH therefore still had ~2 ETH of
phantom headroom each, which `SRLib` reserved and `StakingRouter.topUp` never redistributed,
starving other Active modules.

## Changes

- `SRLib.Config` gains `maxTopUpBalance`; the 0x02 top-up capacity is now computed against
  the executable per-validator ceiling instead of `maxEBType2`.
- `StakingRouter` adds the immutable `MAX_TOP_UP_BALANCE_WC_TYPE_02`, set from the gateway
  `targetBalanceGwei` in deploy scripts and validated to be non-zero and `<= maxEBType2`.
- `ISRBase`: new `InvalidMaxTopUpBalance` error.
- Harness and test deploy helper updated; new regression test covers the 64-validator /
  2046 ETH-per-validator scenario from the issue (128 ETH reserved -> 32 ETH).
